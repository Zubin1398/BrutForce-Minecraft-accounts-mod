> **AuthProbe** — клиентский мод для Minecraft **1.20.1 (Forge)**, который заходит на **offline-mode** сервер под выбранным ником и отправляет пароли из списка через `/l` или `/login`. Несколько ников, у каждого свой список паролей; ровно одна отправка на пароль; кик считается потраченной попыткой; прокси можно вставлять пачкой, проверять и менять по кругу.
>
> Всё управление — локальные сообщения с точкой (`.start`, `.go`, …). Сервер их не видит. Отчёты, статус кика, панель серверного чата и найденный пароль живут на клиенте.

## ✨ Возможности

| | |
|---|---|
| 👥 **Мульти-ник** | Список ников, у каждого свой список паролей. Когда пароли ника кончились — мод закрывает сессию, переподключается под следующим ником и продолжает (с авто-стартом сразу, без него — по `.start` / `.go`). |
| 🗄 **Мульти-сервер** | Список адресов: у каждого свои ники, пароли и метки. Переключение кнопками `<` `>` `+` `-` у поля адреса. |
| 🆔 **2FA** | Сервер просит подтвердить вход → ник помечается красным `2FA`, оставшиеся пароли не тратятся. Метка ставится и до `.start`, если включить проверку. |
| 🧩 **Капча до `.start`** | Сервер просит проверку до логина → прогон встаёт на паузу, ни один пароль не тратится. |
| ⚙ **Для опытных** | Третья страница шаблонов: свои списки `2FA` и `Капча`, три тумблера и кнопка «Снять метки». Шаблоны хранятся отдельно для каждого сервера. |
| 🖱 **Шаблон из чата** | Клик по строке в панели чата → выбор банка → ответ сервера сразу попадает в шаблоны активного сервера. |
| 🎯 **Одна попытка на пароль** | Жёстко, без множителя. 5 паролей = 5 отправок. Кик/вылет после отправки тоже считается попыткой. Единственное исключение — пауза сервера при включённой умной задержке. |
| 🔁 **Экран кика** | Вместо ванильного отключения: текущий ник, отчёт по никам и паролям, последний пароль, следующий шаг, причина, её разбор и смена прокси. |
| 🚫 **Кик по нику** | «Уже онлайн» → оранжевая метка `был онлайн`, «неверный ник» → красная `неверный ник`. Оба случая пропускают ник, не тратя оставшиеся пароли; метки сохраняются после перезапуска. |
| ⏳ **Умная задержка** | Отдельный переключатель: строку «подождите N сек» мод выдерживает сам, повторяет тот же пароль и не списывает попытку. Кнопка «Пауза» при этом неактивна. |
| 🏷 **Метки пропущенных ников** | Ник, отброшенный по «уже онлайн», остаётся в профиле с пометкой `был онлайн · дата`; «неверный ник» помечается красным как постоянный. Пароли не теряются — повторяешь вручную, когда захочешь. |
| 🧾 **Редактируемые причины кика** | Два набора: «кик по нику» и «кик по IP / прокси». Нестандартная формулировка сервера правится в игре, без пересборки. |
| 🌐 **Proxy** | SOCKS5 (с логином/паролем и без) и HTTP CONNECT. Пачечная вставка, проверка списком, ротация по кругу. |
| 🧠 **Разбор ответов** | Четыре набора шаблонов (успех / провал / пауза / кик), системный чат + актионбар, регистронезависимый поиск подстрок. |
| 💾 **Память** | Ники, пароли, последний ник/пароль, настройки, шаблоны и прокси переживают перезапуск и краш. |
| 💬 **Живой чат** | Панель серверного чата: перенос длинных строк, прокрутка колесом, ползунок, очистка. |
| 🟡 **Debug-логи** | Показывают пароль каждой попытки в локальном чате жёлтым. Найденный пароль — зелёным. |
| 🎛 **Мастер-выключатель** | Кнопка **Мод: вкл/выкл** для обычной игры: чат не логируется, точка не перехватывается, перебор не тикает. |
| ⌨ **Макрос** | Кнопка **Макрос .start/.go** + бинд в Управлении: нажатие клавиши в игре запускает/продолжает перебор без ввода команды. |
| 📥 **Импорт .txt** | Импорт ников и паролей из текстового файла: **Заменить** весь список или **Добавить** с объединением дубликатов. |
| 🧩 **Локализация** | Русский и английский интерфейс. |

### 🆕 Что нового в 1.6.1

- **Кик по нику разделён на два списка:** `Ник занят / онлайн` (оранжевая метка) и `Неверный ник` (красная). Совпали оба — побеждает «неверный ник». Зашитый список постоянных фраз удалён, всё настраивается.
- **Новые дефолты:** `уже онлайн` в списке занятых ников, `неправильно указали ник` — в списке неверных. Старый общий `nickKicks` при загрузке раскладывается по двум спискам автоматически.
- **Банк «Провал» дополнен:** `неправильно указан логин/пароль`, `неверно указан логин/пароль`.
- **Список «Неверный ник» дополнен:** `неправильно указан ник`, `неправильно указали ник`, `неверно указан ник`.
- **Новое поведение «проверка пароля».** Строка паузы без числа — это удержание: мод ничего не отправляет, ждёт ответ и не тратит пароль; лимит удержания настраивается.
- **Настройка «Ожидание»**: 1/2/3/5/8/10/15 секунд, по умолчанию 3; сохраняется в конфиг.
- **Настройка «Удержание»**: 5/10/15/20 секунд, по умолчанию 15. Пока сервер сам пишет, что проверяет пароль, короткое «Ожидание» не списывает попытку — пароль ждёт до лимита удержания.
- **Диагностика 2FA и каналов сервера:** при Debug-логах в `latest.log` пишутся строки актионбара, overlay-чата, титула и субтитра, совпадения шаблона 2FA и причина, по которой строка не помечена.
- **Заголовок шаблонов с номером сервера**: `Шаблоны — адрес (1/2)`.
- **Предупреждение о повторном адресе** при вводе адреса, который уже есть у другого сервера.
- **Все предупреждения теперь дублируются тостом**, а не только сообщением в чат.
- **Реконнект:** добавлены значения 1 и 2 секунды.
- **Непонятные символы:** невидимые служебные символы нормализуются перед сравнением и не участвуют в разборе. Раньше заголовок из таких символов мог совпасть с шаблоном и пометить ник как 2FA.
- **Титул и субтитр теперь тоже читаются:** 2FA ловится не только из чата и актионбара, но и из `title`/`subtitle` — на некоторых серверах приглашение приходит именно туда.
- **Разбор пауз:** единицы времени читаются целиком, включая `секунды`, `секунду`, `секунда`.
- **Сообщение о смене ника:** `[AuthProbe] Ник: №2/11 KMC_Po_DoTkKE` + тост, как при смене прокси.
- **Логи в панели размечены цветами** по смыслу, а не все оранжевым.
- **Убран двойной префикс** `[AuthProbe] [AuthProbe]` у стилизованных строк (шапка ника, пароль, пауза, прокси, пропуск ника).
- **Третья страница шаблонов «Для опытных».** Два редактируемых списка — `2FA` и `Капча` — и три переключателя: обнаружение 2FA, 2FA до `.start`, капча до `.start`.
- **Шаблоны на каждый сервер.** `Успех`, `Провал`, `Пауза`, `Кик`, `2FA` и `Капча` теперь хранятся в `servers[]` отдельно для каждого адреса; причины кика остаются общими. Старые общие списки при первом запуске копируются во все серверы.
- **Кнопка `T` у адреса** открывает шаблоны активного сервера; в заголовке экрана адрес выделен голубым. Область действия каждого поля помечена бейджем: `сервер` или `общий`.
- **Клик по строке в панели чата** открывает окно «Добавить в шаблоны» с выбором банка: ответ сервера переносится в настройки одним кликом, без ручного набора.
- **2FA до `.start`.** Если включено, метка ставится сразу после входа, до первой отправки: пароли не тратятся, мод уходит на следующий ник. При автостарте продолжает сам.
- **Капча как стоп-сигнал.** Если до первой отправки сервер просит капчу, прогон встаёт на паузу: `капча — пройди проверку и нажми .start / .go`. При автостарте мод ждёт 750 мс после входа, чтобы промпт успел прийти.
- **Команда `.2fa`.** Помечает текущий ник как `2FA` и уводит на следующий, строка на сервер не уходит. Работает даже при выключенном обнаружении.
- **Сработавший шаблон в строке:** `nick #2/3 (Alex) 2FA · «подтвердите»`.
- **Проверка шаблонов при сохранении:** предупреждения о слишком коротких фразах, дублях между списками и пересечении с банками успеха/провала.
- **Кнопка «Снять метки»** — очищает метки пропусков у всех ников текущего сервера.
- **Исправлено:** `Подтвердите вход в боте` больше не считается капчей. Голые `бот` и `робот` убраны из маркеров, вместо них `не бот` / `не робот`.
- **Поле «Кик / флуд» переименовано в «Лимит / флуд»** и больше не содержит `ip` и `заблокирован`: это слова причины отключения, им место на странице «Причины кика».
- **Результат ника:** после прогона сохраняется, подошёл пароль или все пароли оказались неверными. Если пароль найден, в профиле остаётся только он. Статус виден рядом с ником: `пароль найден` зелёным, `пароли не подошли` серым.
- **Массовое удаление:** кнопки `2FA` (удалить профили с меткой `2FA`) и `0` (удалить профили без верного пароля) рядом со строкой ника, с подтверждением вторым кликом.
- **Экспорт зелёных ников:** кнопка `TXT` рядом со строкой ника сохраняет все ники с найденным паролем в `config/authprobe-success.txt`. Файл группируется по адресам серверов, в каждой строке `ник:пароль`.
- **Сортировка профилей:** кнопка `↑↓` переставляет ники текущего сервера по статусу: `2FA` → `неверный ник` → `пароли не подошли` → `зелёные` → `онлайн` → без метки. Порядок сохраняется в конфиг, активный ник остаётся выбранным.
- **Зелёный результат защищён:** если по нику уже найден пароль, повторный кик «уже онлайн» больше не заменяет зелёную метку оранжевой. Результат `пароль найден` остаётся, пока ник не изменят или не сбросят вручную.
- **Импорт с двумя режимами:** кнопка **Заменить** удаляет текущие профили и загружает файл, кнопка **Добавить** ничего не удаляет. Дубликаты ников объединяются без учёта регистра: недостающие пароли дописываются, метки сохраняются, а серый результат сбрасывается, если появились новые пароли.
- **Ползунок в списке паролей:** поле листается не только колесом, но и перетаскиванием ползунка справа.
- **Успех по пакету входа:** на лимбо-серверах пароль считается найденным, даже если сервер не пишет об успехе в чат.
- **Обход бага Forge:** повторная установка `forge:vanilla_filter` пропускается — клиент больше не падает с `Duplicate handler name` при переводе после верного пароля.
- **Авто-старт продолжает после смены ника** — больше не нужно жать `.start` на каждом новом профиле при включённом авто-старте.
- **Меньше дублей в чате:** после перехода на новый ник не печатается debug-шапка `nick #N/M`, а сообщение о входе больше не повторяет позицию — её показывает следующая строка.
- **Счётчик отправок по текущему нику** в строке позиции; общий итог виден на экране кика (`N на нике · M всего`) и в сообщении о найденном пароле.
- **Конец прогона:** когда все пароли всех ников исчерпаны, мод сам отключается и открывает экран итогов; кнопки «Продолжить» и «Сменить прокси» там неактивны. Если пароль найден — отключения нет, остаёшься в игре.
- **Авто-смена ника** — новый тумблер. Вкл: мод сам переходит к следующему нику и подключается (как раньше). Выкл: останавливается на итогах, следующий ник выбираешь в меню сам.
- **Успех по респавну:** если сервер после верного пароля просто телепортирует в лобби без сообщения в чат, мод распознаёт это по пакету респавна.
- **Успех по телепорту и плагин-каналу:** после «проверка пароля» мод считает вход успешным, если приходит телепорт или плагин-сообщение лобби (например, `vv:server_details`). Раньше правильный пароль на таком сервере не распознавался и мод отправлял следующий.
- **Исправлено:** после исчерпания паролей ника авто-старт не подхватывал следующий ник и мод ждал `.start`. Теперь правило одно для всех переходов: авто-старт вкл — продолжает сам, выкл — ждёт команду.

### 🆕 Что нового в 1.6.0

- **Мульти-сервер.** У поля «Адрес сервера» появились кнопки `<` `>` `+` `-`: каждый сервер хранит свой список ников, свои пароли и свои метки. Прокси-лист и «Последний: ник / пароль» остаются общими. Автоперехода между серверами нет — кончились ники, прогон завершается.
- **Метка `2FA`.** Если после отправки пароля сервер просит подтвердить вход, ник помечается красным `2FA`, оставшиеся пароли не тратятся, мод идёт к следующему нику. В чат и лог пишется `[AuthProbe] nick #2/3 (Alex) 2FA`.
- **Защита от капчи.** Строка, где есть `капча`, `робот`, `бот`, `captcha`, `robot`, `антибот`, никогда не считается запросом 2FA.
- **Схема конфига:** `servers[]` вместо одного `address`; старый файл мигрирует автоматически.

### 🆕 Что нового в 1.5.6

- **Логи в панели чата.** При включённых **Debug-логах** локальные строки `[AuthProbe]` (шапка ника, каждая отправка пароля, паузы, смена прокси, кики) дублируются в панель «Чат сервера» жёлтым. Историю прогона видно в меню, не листая игровой чат.
- **Свои строки не влияют на разбор.** Локальные записи не участвуют в определении успеха или провала, поэтому мод не может прочитать собственный вывод как ответ сервера.
- **Буфер панели — 200 строк** вместо 80.
- **Переключатель «Только логи»** рядом с «Очистить чат»: панель показывает только строки `[AuthProbe]`, серверный чат скрывается. Работает при включённых Debug-логах и на разбор ответов не влияет.

### 🆕 Что нового в 1.5.5

- **Умная задержка.** Новый переключатель **Умная задержка: вкл/выкл** перед кнопкой «Пауза». Когда включён, мод сам читает строку сервера «подождите N сек», выдерживает паузу и **повторяет тот же пароль**, не списывая попытку. Кнопка «Пауза» при этом становится неактивной: базовый интервал берётся из её сохранённого значения.
- **Разбор пауз.** Длительность читается только там, где рядом с числом стоит единица времени (`сек`, `секунд`, `с`, `s`, `sec`, `мин`, `min`). Числа без единицы (`у вас 3 попытки`, `онлайн 250 игроков`) игнорируются. Пауза зажимается в 1…300 секунд, без числа берётся базовый интервал.
- **Лимит повторов.** Один пароль повторяется после паузы не больше трёх раз. Если сервер тормозит четвёртый раз подряд, пароль считается потраченным — прогон не встаёт навсегда.
- **Метки пропущенных ников.** Ник, отброшенный по «уже онлайн», получает метку `был онлайн · 27.10 14:32` (оранжевая) и она **сохраняется в конфиге**. «Неверный ник» помечается красным как постоянный. Метка снимается сама при успешном входе под этим ником или при изменении текста ника, плюс есть маленький `×` рядом с меткой.
- **Редактор причин кика.** Экран «Шаблоны» разделён на две страницы: **Ответы чата** (`успех` / `провал` / `пауза` / `кик`) и **Причины кика** (`кик по нику` / `кик по IP и прокси`). Наборы причин больше не зашиты в код — их можно править под свой сервер.
- **Проверка по границам слова.** Короткие латинские шаблоны (`ip`, `vpn`) теперь ищутся как целые слова: `VIP_Player joined the game` больше не считается киком по IP и не жжёт пароль.
- **`ip` в причинах кика.** Причина ровно `IP` в окне кика распознаётся как IP-фильтр → смена прокси.
- **Экран кика:** строка `Распознано: ...` (ник занят / неверный ник / IP-прокси / не распознана) и счётчик `Паузы сервера: N`.

## ⚡ Быстрый старт

**1) Установка**

Скачать `AuthProbe-1.6.1+1.20.1-forge.jar` и положить в:

```text
%APPDATA%\.minecraft\mods\
```

Запустить **Minecraft 1.20.1 с Forge 47.3.19+**. Мод клиентский — на сервер его ставить не нужно.

**2) Открыть меню**

Главный экран → кнопка **AuthProbe** в правом нижнем углу.

**3) Заполнить**

1. **Адрес сервера** — `host` или `host:port`. Кнопки `<` `>` `+` `-` рядом переключают и добавляют серверы; `T` открывает шаблоны активного сервера, у каждого адреса свои ники и пароли.
2. **Ник** — 3–16 символов, `A-Z a-z 0-9 _`.
3. **Пароли** — по одному в строке.
4. Кнопки `<` `>` `+` `-` рядом с ником добавляют и переключают профили внутри сервера.
5. **Импорт .txt** — загрузить ники и пароли из файла (формат ниже) в **активный** сервер: **Заменить** или **Добавить**.
6. **Начать** — мод подменит сессию и подключится.

**4) Запустить перебор**

В чате:

```text
.start
```

Можно вместо команды нажать назначенную клавишу, если включён **Макрос .start/.go** (биндится в Управлении).

Дальше мод сам отправляет пароли и ждёт ответ. Когда пароли ника кончаются — закрывает сессию, переподключается под следующим ником и продолжает: с включённым **Авто-стартом** сразу с его первого пароля, без него — по `.start` / `.go`. Когда кончились все — `EXHAUSTED`, мод отключается и показывает экран итогов.

**5) Забрать результат**

В чате появится зелёный пароль:

```text
[AuthProbe] PASSWORD FOUND: hunter2 (password #3 of 12, 5 sends total)
```

При кике откроется экран состояния с последним паролем и следующим шагом.

## 🖥️ Интерфейс

<img src="./docs/screenshots/MainAuthProbe.svg" width="100%" alt="Схема экрана AuthProbe: список серверов, профиль, пароли, параметры, чат"/>

<sub>**Схема интерфейса, не скриншот.** Слева сервер, профиль и пароли, справа параметры и живой чат, снизу действия.</sub>

### Поля профиля

| Элемент | Что делает |
|---|---|
| **Адрес сервера** | `host` или `host:port`; проверяется до подключения. Рядом `<` `>` — переключение сервера, `+` — новый сервер, `-` — удалить текущий, `T` — шаблоны этого сервера. `ServerAddress.parseString` на мусоре молча уходит в `localhost`, поэтому адрес валидируется отдельно. |
| **Ник (N/M)** | Активный профиль. Рядом `<` `>` — переключение, `+` — новый ник, `-` — удалить текущий, красный `X` — удалить **все** профили текущего сервера, `2FA` — удалить профили с меткой `2FA`, `0` — удалить профили, где ни один пароль не подошёл, `TXT` — экспорт зелёных ников с паролями, `↑↓` — сортировка профилей по статусу. У `2FA` и `0` двойное нажатие: первый клик делает кнопку красным `?`, второй в течение 4 секунд удаляет. |
| **Пароли** | Многострочный список активного ника. Разделитель — только перевод строки. Запятые/точки с запятой/пробелы разделителями не являются. Дубликаты схлопываются, порядок первого вхождения сохраняется. Максимум 2048. Листается колесом и перетаскиванием ползунка справа. |
| **Последний** | Последний ник и пароль, реально ушедшие на сервер; сохраняются между запусками. |
| **Состояние** | Текущее состояние прогона (`WAIT_SEND`, `SENT`, `DISCONNECTED`, …). |
| **паролей** | Сколько паролей в активном профиле. |
| **адрес / ник** | Валидность, зелёным или красным. |

### Панель параметров

Клик по кнопке переключает значение. У каждой есть подсказка при наведении.

| Кнопка | Значения | По умолчанию | Смысл |
|---|---|---|---|
| **Мод** | вкл / выкл | вкл | мастер-выключатель: при выкл. чат не логируется, точка не перехватывается, перебор не тикает |
| **Макрос .start/.go** | вкл / выкл | выкл | разрешить бинд-клавише из Управления запускать/продолжать перебор |
| **Вход** | `/l <пароль>` ↔ `/login <пароль>` | `/l` | какую команду входа отправлять |
| **Умная задержка** | вкл / выкл | выкл | самому выдерживать паузу сервера и повторять тот же пароль; при вкл. кнопка «Пауза» неактивна |
| **Пауза** | 0 / 100 / 200 / 400 / 800 / 1200 / 1500 / 2000 / 3000 мс | 1200 | пауза между отправками; 0 — отправка на следующем тике. При умной задержке — базовый интервал |
| **Ожидание** | 1 / 2 / 3 / 5 / 8 / 10 / 15 с | 3 | сколько ждать ответа на отправленный пароль, прежде чем считать попытку потраченной; после «проверка пароля» ожидание продлевается до лимита удержания |
| **Удержание** | 5 / 10 / 15 / 20 с | 15 | сколько ждать ответа после того, как сервер сам сообщил «проверка пароля», прежде чем списать пароль |
| **Реконнект** | 0 / 1 / 2 / 3 / 5 / 8 / 15 / 30 с | 8 | задержка перед автопереподключением |
| **Авто-старт** | вкл / выкл | выкл | начинать перебор сразу после первого входа, без `.start`; при авто-смене следующий ник продолжает сам |
| **Авто-смена ника** | вкл / выкл | вкл | сам переходить к следующему нику и подключаться. Выкл — мод останавливается и показывает итоги, следующий ник выбираешь вручную |
| **Debug-логи** | вкл / выкл | выкл | писать пароль каждой попытки в локальный чат жёлтым |
| **Прокси** | вкл / выкл | выкл | направлять подключение через прокси; `...` открывает список и проверку |
| **Авто-реконнект** | вкл / выкл | вкл | переподключаться после кика; при IP-бане, VPN/Proxy-фильтре или тайм-ауте сначала сменить прокси |

**Про «Вход».** Слэш на сервер не уходит: пакет команды несёт имя команды без ведущего слэша. Пароль со знаком `%` подстановку не ломает.

**Про паузу.** При 0 мод отправляет на следующем клиентском тике (~50 мс). Полное время между попытками всё равно включает ожидание ответа сервера (до 3000 мс).

**Про умную задержку.** Когда она включена, кнопка «Пауза» серая и не переключается, но сохранённое значение продолжает работать как базовый интервал между обычными отправками. Если сервер называет паузу, берётся большая из двух величин, но не больше 300 секунд. Повтор одного пароля — не больше трёх раз подряд.

**Про «Мод».** Выключение — режим обычной игры: серверный чат не буферизуется, сообщения с точкой не перехватываются, экран отключения не подменяется, активный перебор останавливается. Состояние сохраняется в конфиге.

**Про Debug-логи.** После подключения один раз печатается шапка `nick #2/3: Alex` (номер голубым, ник жёлтым). Дальше каждая попытка выводит `nick #2/3 · password #3/12: <qwerty>` — номера голубым, пароль жёлтым. Имя ника повторно не дублируется.

### Чат сервера

- Видны системный чат и **актионбар** (актионбар выделен другим цветом).
- Длинные строки **переносятся** по ширине панели.
- История **прокручивается колесом** или **перетаскиванием ползунка** справа.
- Буфер — последние **200** строк.
- **Очистить чат** стирает буфер и сбрасывает прокрутку.
- **Только логи** — панель показывает лишь локальные строки `[AuthProbe]`, серверный чат скрыт. Кнопка активна только при включённых Debug-логах; она не влияет на разбор ответов, только на отображение.
- **Клик по строке** открывает окно «Добавить в шаблоны»: выбираешь банк (`Успех`, `Провал`, `Пауза`, `Кик`, `2FA`, `Капча`, `Кик по нику`, `Кик по IP`), и строка добавляется в шаблоны **активного сервера**. Так ответ сервера переносится в настройки без ручного набора. Локальные строки `[AuthProbe]` в это окно не открываются.
- Локальные строки `[AuthProbe]` в разбор ответов не попадают.
- Если включены **Debug-логи**, локальные строки `[AuthProbe]` дублируются в панель, размеченные по смыслу: служебные — серые, ник и смена ника — бирюзовые, отправка пароля — жёлтая, найденный пароль — зелёный, паузы/капча/2FA — оранжевые, пропуск ника и ошибки — красные, прокси — фиолетовые. Так историю прогона видно в меню, не листая игровой чат.

### Нижние кнопки

| Кнопка | Действие |
|---|---|
| **Начать** | сохранить поля → проверить адрес/ник/пароли/прокси → подменить сессию → подключиться |
| **Стоп** | остановить прогон и напечатать позицию |
| **Импорт .txt** | открыть импорт: **Заменить** текущие профили или **Добавить** новые с объединением дубликатов |
| **Шаблоны** | редактор ответов сервера и причин кика (две страницы) |
| **В меню** | сохранить и вернуться |

<a id="nicks"></a>

## 👥 Мульти-ник

Каждый ник — отдельный профиль со своим списком паролей. Каждый **сервер** держит свой независимый набор таких профилей: переключение адреса кнопками `<` `>` подгружает ники и пароли именно этого сервера, а метки пропусков остаются при своих адресах.

```text
Ник (2/3)
┌──────────────────────────────┐ ┌───┐ ┌───┐ ┌───┐ ┌───┐
│ Alex                         │ │ < │ │ > │ │ + │ │ - │
└──────────────────────────────┘ └───┘ └───┘ └───┘ └───┘
```

- `<` / `>` сохраняют текущие поля и загружают соседний профиль.
- `+` добавляет пустой профиль, `-` удаляет текущий (последний удалить нельзя).
- Когда `passwordIndex` выходит за конец списка текущего ника, мод:
  1. ставит смену профиля в очередь на следующий тик;
  2. закрывает старую сессию;
  3. подменяет offline-сессию на следующий ник;
  4. переподключается и продолжает: с включённым **Авто-стартом** сразу с первого пароля, без него — по `.start` / `.go`.
- Это всегда **новое подключение**: старый сокет закрывается, ник в handshake меняется, in-place переименования нет. Искусственной паузы между коннектами нет — только следующий клиентский тик.
- **Авто-смена ника** решает, переходить ли к следующему профилю; **Авто-старт** — начинать ли отправку сразу после входа. Если включены оба, переход и отправка идут без команд. Если авто-смена выключена, мод останавливается на итогах и ждёт, пока ты выберешь ник.
- Пустые ники/списки при переходе пропускаются.
- `Далее: ник / пароль` на экране кика показывает следующий шаг, включая следующий ник.
- При переходе на следующий ник в чат приходит `[AuthProbe] Ник: №2/11 KMC_Po_DoTkKE` и тост — в том же стиле, что и сообщение о смене прокси. Отдельная debug-шапка `nick #N/M` после такого перехода не печатается, чтобы не дублировать ник.

### Результат ника и массовое удаление

Каждый ник помнит, чем закончилась проверка, и это видно рядом с подписью `Ник (N/M)`:

- **`пароль найден`** — зелёным; в списке остаётся **только** тот пароль, который подошёл;
- **`пароли не подошли`** — серым; все пароли перебраны, ни один не сработал.

Крестик `×` рядом с меткой снимает и метку пропуска, и результат. На экране кика статус показывается той же строкой.

Рядом со строкой ника четыре кнопки:

| Кнопка | Действие |
|---|---|
| `2FA` | удалить все профили текущего сервера с меткой `2FA` |
| `0` | удалить профили, где ни один пароль не подошёл (пропущенные и непроверенные не трогаются) |
| `TXT` | экспортировать все зелёные ники всех серверов с паролями в `config/authprobe-success.txt` |
| `↑↓` | отсортировать профили текущего сервера по статусу |

Кнопки `2FA` и `0` требуют **двойного нажатия**: первый клик превращает кнопку в красный `?`, второй в течение 4 секунд выполняет удаление. После этого в чат приходит число удалённых профилей.

**Сортировка `↑↓`** работает только для текущего сервера и только когда прогон не идёт. Порядок сверху вниз:

1. метка `2FA`;
2. `неверный ник`;
3. `пароли не подошли`;
4. `пароль найден` — зелёные;
5. `был онлайн`;
6. без метки и без результата.

Внутри каждой группы порядок не меняется. Активный ник остаётся выбранным — меняется только его номер `(N/M)`. Новый порядок сохраняется в `authprobe.json`, и экспорт `TXT` идёт уже в нём.

**Экспорт `TXT`** берёт только ники с результатом `пароль найден` — зелёные. Серверы без зелёных ников в файл не попадают, активный сервер при экспорте не переключается. Формат:

```text
# AuthProbe — успешные ники
# 30.10.2026 23:20

[mc.politmine.ru]
feelsmango:12345678.
virusbos:12345678.

[play.example.com]
Nick:pass
```

Кнопка неактивна, пока зелёных ников нет; в подсказке видно их количество. После записи в чат и тост приходит `экспортировано N ников → config/authprobe-success.txt`. Файл перезаписывается при каждом экспорте.
- `EXHAUSTED` — только когда кончились **все** ники. Мод сам отключается и открывает экран итогов. Если пароль найден, отключения нет: остаёшься в игре.

### Метки пропущенных ников

Ник, отброшенный по причине «уже онлайн», не теряется: он остаётся в профиле со всем списком паролей и получает метку рядом с подписью `Ник (N/M)`:

- `был онлайн · 27.10 14:32` — оранжевая, кик временный, повторить имеет смысл позже;
- `неверный ник` — красная, сервер не примет это имя, повторять бессмысленно;
- `2FA` — красная, аккаунту нужно подтверждение входа; пароль мог подойти, остальные пароли не тратятся.

Метка хранится в `config/authprobe.json` и переживает перезапуск и краш. Снимается сама при успешном входе под этим ником и при изменении текста ника; рядом с меткой есть маленький `×` для ручного снятия.

Мод **не** перезапускает такие ники по таймеру. Когда решишь, что прошло достаточно времени, выбери ник и нажми «Начать» — пароли уже на месте. Метка ничего не блокирует, она только напоминает.

## ⌨ Макрос .start/.go

1. Включи **Макрос .start/.go** в параметрах.
2. Открой **Настройки → Управление → AuthProbe** и назначь клавишу на **«Запуск подбора (.start/.go)»**.
3. В игре, без открытого чата или меню, нажми клавишу — мод выполнит то же, что `.start` / `.go`: начнёт с #1 или продолжит с сохранённой позиции.

Клавиша по умолчанию **не назначена**. Макрос работает только при включённом моде и включённой кнопке макроса; в меню и чате не срабатывает.

<a id="import"></a>

## 📥 Импорт .txt

Кнопка **Импорт .txt** открывает окно импорта: оно пытается показать системный проводник. Если игра запущена с `-Djava.awt.headless=true` (например, TLauncher), проводник недоступен — вставь путь в поле или содержимое файла в большое поле вручную. **Обзор** только подставляет путь к файлу; дальше выбери режим:

- **Заменить** — удаляет текущие профили активного сервера и загружает файл;
- **Добавить** — ничего не удаляет: новые ники добавляются в конец, существующие остаются на месте.

Формат:

```text
frantic | АСПИД
hentay
nailpan12
boss123

dima228 | ДОНАТ
2015228
123456789b
```

- `ник | что угодно` — заголовок нового ника; всё после `|` игнорируется (например донатная привилегия).
- Каждая непустая строка после заголовка — пароль этого ника.
- Пустые строки между паролями и следующим ником игнорируются, их может быть сколько угодно.
- Следующая строка с `" | "` начинает новый ник.
- Одинаковые ники в файле объединяются.
- В режиме **Добавить** ник сравнивается без учёта регистра: `Nick` и `nick` — один профиль. Недостающие пароли дописываются к существующему, его метка сохраняется. Если у профиля стоял серый результат `пароли не подошли`, а импорт добавил новые пароли, результат сбрасывается.
- Если у существующего профиля уже стоит `пароль найден`, его список не трогается — остаётся только найденный пароль.
- Если у дубликата нет новых паролей, он пропускается. В чат приходит `добавлено N, объединено M, пропущено K`.
- Кодировка UTF-8; если файл не UTF-8, пробуется windows-1251.
- Адрес сервера, прокси и остальные настройки импорт не трогает.
- После **Заменить** или **Добавить** окно настроек сразу показывает новый список.

<a id="commands"></a>

## 💬 Команды

Вводятся как **обычное сообщение с точкой**, не как `/`-команда. Перехватываются на клиенте и не уходят на сервер. Гасится **любое** сообщение, начинающееся с точки, включая опечатки.

| Команда | Что делает |
|---|---|
| `.start` / `.go` | начать с пароля №1; если прогон уже был начат (например, после «Продолжить»), продолжить с текущей позиции |
| `.stop` | остановить прогон и напечатать позицию |
| `.status` | состояние, индекс пароля, последний пароль, количество отправок |
| `.2fa` | пометить текущий ник как `2FA` и перейти к следующему, не отправляя строку на сервер |
| `.help` | список команд |

Опечатка вроде `.strat` тоже не уйдёт на сервер:

```text
[AuthProbe] unknown command '.strat'. .help - command list
```

**Почему точка, а не слэш.** Сообщения с `/` идут через `ClientCommandHandler` и перехвату не подлежат. Сообщения с `.` идут обычным чатом, где событие можно отменить.

**Уведомления мода** — локальные, с префиксом `[AuthProbe]`; сервер их не получает.

<a id="detection"></a>

## 🧠 Как определяется успех и провал

Мод слушает пять каналов сервера:

1. **системный чат** — `ClientChatReceivedEvent`;
2. **актионбар** — отдельный mixin на `setActionBarText`, потому что этот пакет не приходит в событие чата;
3. **overlay-чат** — системный чат с флагом `overlay`, который клиент рисует в актионбаре;
4. **титул** и **субтитр** — `setTitleText` / `setSubtitleText` тем же миксином.

Боссбар мод не читает. Все каналы попадают в один разбор, поэтому шаблоны работают одинаково независимо от того, куда сервер написал текст.

**Успех без сообщения.** На лимбо-серверах после верного пароля мод видит один из сигналов перевода: **второй пакет входа**, **респавн**, **телепорт** или **плагин-канал** лобби (`vv:server_details` и подобные). Телепорт и плагин-канал засчитываются только после того, как сервер сам написал «проверка пароля», поэтому обычные пакеты в лимбо не дают ложного успеха. В любом случае пароль найден, список обрезается до него.

**Обход бага Forge.** На таком переводе Forge 1.20.1 падал с `Duplicate handler name: forge:vanilla_filter`: сетевой фильтр добавлялся в конвейер второй раз. Мод пропускает повторную установку, если фильтр уже стоит, поэтому перевод проходит.

Проверка — **вхождение подстроки без учёта регистра**. Порядок: **2FA → капча → успех → провал → пауза → кик**. Первое совпадение выигрывает.

2FA и капча проверяются отдельно от обычных ответов, потому что 2FA нужно видеть и до `.start`, а капча не должна читаться как 2FA.

Короткие латинские шаблоны (до трёх символов, только буквы и цифры: `ip`, `vpn`) ищутся **как целые слова**. Поэтому `VIP_Player joined the game` не считается баном по IP, а `Your IP is blocked` — считается. Более длинные шаблоны работают как подстрока.

### Шаблоны по умолчанию (сток AuthMe, EN + RU)

| Набор | Подстроки |
|---|---|
| **Успех** | `logged in`, `successfully logged`, `you are now logged`, `успешно`, `вы вошли`, `авторизован`, `вход выполнен`, `успешный` |
| **Провал** | `wrong password`, `incorrect password`, `invalid password`, `password is wrong`, `неверный пароль`, `неправильный пароль`, `неверный логин`, `неправильный логин`, `неправильно указан логин`, `неправильно указан пароль`, `неверно указан логин`, `неверно указан пароль` |
| **Пауза** | `подождите`, `подожди`, `не так быстро`, `проверка пароля`, `please wait`, `wait before`, `slow down`, `too fast`, `not so fast` |
| **Лимит / флуд** | `too many`, `слишком много`, `kicked`, `flood`, `spam`, `попыток` |

Этот банк отвечает только за **ответ в чате**: сервер отказал попытке из-за лимита, пароль списывается, мод идёт дальше. Слова вроде `ip`, `vpn`, `заблокирован` здесь не нужны — они относятся к **причине отключения** и живут на странице «Причины кика», где меняют прокси и пропускают ник.

### Умная задержка и пауза сервера

Отдельная кнопка **Умная задержка: вкл/выкл** стоит прямо перед «Паузой».

| Состояние | Кнопка «Пауза» | Поведение |
|---|---|---|
| **выкл** (по умолчанию) | активна, `0 / 100 / 200 … 3000 мс` | как раньше: строка «подождите» считается киком, пароль списывается |
| **вкл** | неактивна, серая | пауза выдерживается, тот же пароль отправляется повторно, попытка не тратится |

Что именно выдерживается:

- число берётся **только** вместе с единицей времени: `30 сек`, `45 секунд`, `10 секунды`, `15s`, `2 minutes`, `1 мин`;
- числа без единицы игнорируются: `у вас 3 попытки`, `онлайн 250 игроков`;
- пауза зажимается в **1…300 секунд**;
- если числа нет (`проверка пароля`, `просто подождите`) — это **удержание**: мод ничего не отправляет, просто ждёт ответ; пароль не тратится;
- пока удержание активно, короткое **Ожидание** не списывает пароль: попытка ждёт до лимита **Удержания** (5 / 10 / 15 / 20 с, по умолчанию 15); когда лимит истекает, в локальном чате появляется `удержание истекло (N с) — пароль списан`;
- один пароль повторяется не больше **трёх раз** (только для паузы с числом); четвёртая пауза подряд означает, что пароль считается потраченным.

Это единственное исключение из правила «один пароль = одна отправка»: сервер просит паузу **до** проверки пароля, поэтому попытка не потрачена. В локальном чате видно `сервер просит паузу 30 с — повтор пароля #3/12 (1/3)`.

### 2FA и капча

2FA и капча — это два сигнала, которые ловятся **не как обычные ответы**, а отдельно: 2FA нужно видеть ещё до `.start`, а капча не должна читаться как 2FA.

**2FA.** Если сервер просит подтвердить вход, ник получает красную метку **`2FA`**, оставшиеся пароли не тратятся, мод переходит к следующему нику. В чат и лог уходит `[AuthProbe] nick #2/3 (Alex) 2FA · «подтвердите»` — сработавший шаблон видно сразу.

Строка ищется во всех каналах: чат, актионбар, overlay-чат, титул, субтитр. На практике встречаются оба варианта: на одном сервере приглашение приходит обычным сообщением в чат, на другом — титулом `Подтвердите вход` с субтитром `В боте Telegram`. Мод ловит и то, и другое.

Где ловится:

| Момент | Условие |
|---|---|
| после отправки пароля | всегда, если включено **Обнаружение 2FA** |
| до первой отправки | только если на третьей странице шаблонов включено **2FA до `.start`** |

Если 2FA пришло до `.start`, а проверка выключена — ты видишь строку и пишешь `.2fa`: мод пометит ник и уйдёт на следующий, ничего не отправляя на сервер.

**Капча.** Если до первой отправки сервер просит капчу, мод **встаёт на паузу** и пишет `капча — пройди проверку и нажми .start / .go`. Ни один пароль не тратится. Проходишь проверку, жмёшь `.start` — прогон продолжается с той же позиции. При автостарте мод ждёт 750 мс после входа, чтобы промпт успел прийти.

### Диагностика 2FA и капчи

При включённых **Debug-логах** в `latest.log` пишется, каким каналом пришла строка:

- `action bar: <текст>` — пакет актионбара;
- `action bar (overlay): <текст>` — серверный чат, который клиент рисует в актионбаре;
- `title: <текст>` / `subtitle: <текст>` — титул и субтитр;
- `2FA candidate by '<шаблон>': <текст>` — строка совпала с шаблоном 2FA;
- `2FA for nick #N '...' by '<шаблон>'` — ник помечен и пропущен.

⚠️ `latest.log` пишется в **Windows-1251**. Если открыть его как UTF-8, кириллица превратится в `?` или непонятные символы, и сработавший шаблон будет выглядеть пустым. Читай лог редактором с кодировкой Windows-1251 (Notepad++ → Кодировки → Windows-1251).

Если 2FA-строка распознана, но проверка до `.start` выключена, мод один раз на ник пишет в чат и тост:

```text
2FA замечено («подтвердите»), но 2FA до .start выключено — строка проигнорирована
```

Так сразу видно, дело в шаблоне, в настройке или в том, что сервер вообще не прислал строку.

### Экран «Шаблоны»

**Шаблоны принадлежат серверу.** `Успех`, `Провал`, `Пауза сервера`, `Лимит / флуд`, `2FA` и `Капча` хранятся отдельно для каждого адреса — на трёх серверах с разными плагинами списки не смешиваются. В заголовке экрана адрес активного сервера выделен **голубым** и указан его номер: `Шаблоны - play.example.com (1/2)`, так что одинаковые адреса не путаются. Открыть шаблоны можно кнопкой `T` прямо у поля адреса. Если ввести адрес, который уже есть у другого сервера, мод предупредит в чате и тостом. Общими остаются только причины кика (`Ник занят / онлайн`, `Неверный ник`, `Кик по IP / прокси`) — у этих трёх полей в углу стоит янтарный бейдж **`общий`**. У полей шаблонов ответов и страницы «Для опытных» — бирюзовый бейдж **`сервер`**. Два ник-списка работают так: совпал «онлайн» → оранжевая метка `был онлайн`, совпал «неверный ник» → красная `неверный ник`, совпали оба → побеждает «неверный ник».

Три страницы, кнопка листает по кругу: **Ответы чата → Причины кика → Для опытных → Ответы чата**.

1. **Ответы чата** — `Успех`, `Провал`, `Пауза сервера`, `Лимит / флуд`;
2. **Причины кика** — `Ник занят / онлайн`, `Неверный ник`, `Кик по IP / прокси`;
3. **Для опытных** — два поля шаблонов (`2FA`, `Капча`) и три переключателя:
   - **Обнаружение 2FA** — мастер-выключатель; после `.start` работает всегда, пока он включён;
   - **2FA до `.start`** — активен только при включённом мастере;
   - **Капча до `.start`** — пауза прогона до первой отправки.

Там же кнопка **Снять метки** — убирает все метки пропусков у ников текущего сервера.

По одному шаблону в строке, пустые строки игнорируются. **Сохранить** применяет всё и возвращает назад, **Сбросить** возвращает значения по умолчанию для текущей страницы. Очистить список полностью нельзя: вернутся дефолтные — пустой набор сломал бы разбор.

При сохранении мод предупреждает в чате, если шаблон:
- короче трёх символов — будет ловить обычный чат;
- есть и в `2FA`, и в `Капче` — капча всегда побеждает, 2FA перестанет срабатывать;
- совпадает с банком `Успех` / `Провал` — перебьёт определение пароля.

Те же проверки выполняются при загрузке конфига и один раз при первом входе на сервер: если `authprobe.json` правили руками, предупреждения придут в `latest.log` и в чат. Списки меняются **только** кнопкой «Сохранить» на экране шаблонов, автосейв лишь переписывает уже сохранённое.

Калибровка на неизвестном сервере:

1. Открыть меню и живую панель чата.
2. Сделать одну попытку (`.start`).
3. Посмотреть, какими словами сервер говорит «неверный пароль» и как выглядит приглашение.
4. Вписать реальные фразы в «Провал» и «Успех».
5. Повторить, пока разбор не станет однозначным.

Если сервер отвечает только в актионбар — строки всё равно видны в панели (другим цветом). Если сервер молчит и просто пускает в мир — добавь в «Успех» фразу после входа или ориентируйся на исчезновение «Авторизуйтесь».

## 🔁 Экран кика и вылета

Пока прогон активен, вместо ванильного `DisconnectedScreen` показывается свой:

```text
AuthProbe - отключён
Состояние: отключён
Текущий ник: Alex @ play.example.com:25565
Прокси: №1 / №10
Пройдено ников: 1 · начал с #1 · прерван на #2 из 3
#1 Steve — 12 паролей · пройден
#2 Alex — 5 паролей · текущий
пароль #4/12 (последний: qwerty), отправлено 4
Далее: Alex / 123456
Последний пароль: qwerty
Причина: You have been kicked for too many attempts
Распознано: IP / прокси → смена прокси
Паузы сервера: 2
Авто-продолжение через 7 с
[Продолжить]

```

Отчёт показывает, с какого ника начался прогон, на каком прервался и сколько паролей у каждого ника. Пройденные ники зелёные, текущий жёлтый, пропущенный из-за кика по нику — красный. Длинная причина кика переносится по строкам и не выходит за панель. Если прокси включён, показывается его позиция `№N / №M`.

Строка **Распознано** показывает, как мод прочитал причину: `ник занят (временный)`, `неверный ник (постоянный)`, `IP / прокси` или `не распознана`. Счётчик **Паузы сервера** появляется, только если умная задержка реально выдерживала паузы в этом прогоне.

**Кик по нику.** Два общих списка на странице «Причины кика»:

- **Ник занят / онлайн** — `уже онлайн`, `ник занят`, `already online`, `уже на сервере`… → метка `был онлайн · дата` (оранжевая). Повторить имеет смысл позже.
- **Неверный ник** — `неверный ник`, `invalid username`, `неправильно указали ник`… → метка `неверный ник` (красная). Повторять бессмысленно, пока не изменишь текст ника.

Совпал любой список — мод **не тратит** оставшиеся пароли этого ника и переходит к следующему. Совпали оба — побеждает «неверный ник». Не совпал ни один — обычный кик: пароль списывается, переподключение под тем же ником. Если следующего ника нет — прогон завершается `EXHAUSTED`.

| Кнопка | Действие |
|---|---|
| **Продолжить** | переподключиться и **ждать `.start` / `.go`**; позиция сохраняется, отправка начнётся только по команде и не с первого пароля |
| **Сменить прокси** | взять следующий прокси по кругу, включить прокси-режим и переподключиться (тоже ждёт `.start` / `.go`) |
| **Стоп** | остановить прогон |
| **В меню** | остановить и выйти в главное меню |

**Одна отправка — одна попытка.** Если пароль уже ушёл и сессию выкинуло, он считается использованным: курсор сдвигается на следующий. Повторной отправки того же пароля автоматически не бывает.

«Авто-продолжение через N с» работает при включённом **Авто-реконнекте**. Любая кнопка отменяет отсчёт. Если ничего не нажимать, мод сам переподключится: с **Авто-стартом** продолжит со следующего пароля, без него будет ждать `.start` / `.go`. При **смене ника** ожидание `.start` / `.go` обязательно в любом случае.

**Авто-смена прокси.** Если включены **Авто-реконнект** и **Прокси**, при кике по IP-бану, VPN/Proxy-фильтру или тайм-ауту мод перед переподключением берёт следующий прокси из списка и показывает в чате + тосте `Прокси: №N/M`. На последнем прокси авто-реконнект останавливается и **не переходит на первый** — иначе были бы бесконечные круги. Кнопка **Сменить прокси** на экране кика вручную начинает круг заново. При обычном кике прокси не меняется.

<a id="proxy"></a>

## 🌐 Proxy

<img src="./docs/diagrams/flow.svg" width="100%" alt="Схема прогона: профили, подключение, отправка, ответ, следующий пароль или ник"/>

Proxy включается кнопкой **Прокси**, список и проверка — кнопкой **...** рядом.

### Форматы вставки

Один прокси на строку, `#` — комментарий. Формат определяется автоматически:

| Формат | Пример |
|---|---|
| `host:port` | `127.0.0.1:1080` |
| `user:pass@host:port` | `user:pass@127.0.0.1:1080` |
| `host:port@user:pass` | `127.0.0.1:1080@user:pass` |
| `host:port:user:pass` | `127.0.0.1:1080:user:pass` |
| со схемой | `socks5://user:pass@host:port`, `http://host:port` |
| IPv6 | `[::1]:1080`, `user:pass@[::1]:1080` |

Поддерживаются **SOCKS5** (no-auth и username/password по RFC 1929) и **HTTP CONNECT**.

### Проверка

- **Проверить** — параллельно (8 потоков, тайм-аут 6 с) открывает реальный туннель до адреса сервера из формы.
- Результат и задержка показываются справа: `OK 123 мс` зелёным или `FAIL` красным. Если список не помещается — **листай колесом**.
- **Удалить мёртвые** оставляет только успешные строки.
- **Сохранить** пишет список в конфиг.
- Если адрес сервера не задан — проверка попросит его указать.

**Что именно измеряет проверка.** Проверка идёт до адреса из поля **«Адрес сервера»**. Адрес обновляется при вводе и сохраняется перед открытием `...`; в окне проверки показано `Сервер для проверки: ...`. Если адрес заменили — проверка использует новый. Это не ICMP-пинг и не пинг «прокси ↔ сервер» напрямую. Для каждой строки мод:
1. подключается к прокси;
2. выполняет SOCKS5 / HTTP CONNECT до адреса сервера;
3. замеряет время до установки TCP-туннеля;
4. закрывает соединение.

Minecraft-хендшейк и логин при проверке не отправляются. `OK 123 мс` значит, что **твой клиент через прокси смог открыть TCP до сервера за 123 мс**. Это не гарантирует, что сервер пустит в игру: он может фильтровать VPN/прокси, страну или IP.

### Как это работает

Подключение идёт через локальный loopback-relay: mixin подменяет только TCP-адрес в `Connection.connect`, а handshake по-прежнему строится из исходного `ServerAddress`. Сервер видит настоящий адрес, трафик идёт через прокси.

Если прокси включён, но сломан, мод **не откатывается** на прямое подключение: соединение просто не состоится. Это защита от утечки реального IP.

**Прокси проходит проверку, но вход тайм-аутится.** Проверка открывает реальный TCP-туннель; `OK` значит, что прокси работает. Тайм-аут на логине обычно означает, что сервер блокирует VPN/прокси, ограничивает страну или прокси слишком медленный. В `latest.log` смотри `proxy tunnel established` (туннель есть) и `proxy relay failed` (прокси не подошёл). Попробуй прокси из страны сервера или выключи прокси для проверки.

### Ротация

На экране кика **Сменить прокси** берёт следующий прокси по порядку (если список не закончился), **включает** прокси-режим и сразу переподключается. На последнем прокси кнопка заворачивает на первый — вручную начинает новый круг. Авто-реконнект делает то же только до последнего прокси и затем останавливается. Позиция ротации сохраняется в конфиге.

**Когда мод выключен**, прокси-маршрутизация тоже отключается: соединения идут напрямую, даже если переключатель прокси был сохранён включённым. Кнопка **Прокси** в меню при этом неактивна.

## 💾 Сохранение и конфиг

Всё состояние лежит в:

```text
%APPDATA%\.minecraft\config\authprobe.json
```

Сохраняются:

- список серверов, у каждого свой адрес, свои профили ников, свои пароли и **свои шаблоны ответов**;
- активный сервер и активный ник внутри каждого сервера;
- последний отправленный ник и пароль;
- метки ников: `был онлайн`, `неверный ник`, `2FA`;
- `mode`, `delayMs`, `timeoutMs`, `reconnectDelayMs`, `smartDelay`, `autoStart`, `autoReconnect`, `debugLogs`, `logsOnly`, `modEnabled`, `macroEnabled`;
- у каждого сервера: `success`, `fail`, `wait`, `kick`, списки `twoFactor` / `captcha` и тумблеры `twoFactorDetection`, `twoFactorBeforeStart`, `captchaBeforeStart`;
- общие причины кика `nickKicks` / `proxyKicks`;
- список прокси, позиция ротации, `proxyEnabled`.

<a id="privacy"></a>

## 🔒 Приватность

- Ники, пароли, прокси и шаблоны **хранятся на диске открытым текстом** в `config/authprobe.json`. Шифрования нет. Не оставляй файл на чужой машине.
- В `latest.log` попадают индексы и количество отправок (без пароля), **последний использованный пароль** и **найденный пароль**.
- В локальный чат попадают те же отчётные строки, включая последний пароль; `.status` тоже его печатает.
- С **Debug-логами** пароль каждой попытки печатается в локальный чат жёлтым. Сервер эту строку не получает, но она остаётся в истории чата.
- Проверка прокси открывает TCP-туннель до адреса сервера через каждый прокси; пароли Minecraft прокси не передаются — только логин/пароль прокси, если он задан.
- Если не хочешь оставлять пароль в логе и чате — очисти поле паролей после находки и не вызывай `.status`.

<a id="troubleshooting"></a>

## 🩺 Разбор проблем

| Симптом | Причина / что делать |
|---|---|
| Мода нет в списке модов | Не тот профиль/версия. Нужен Forge 1.20.1 с Forge ≥ 47.3.19. Смотреть `latest.log` на строки `AuthProbe`. |
| Кнопки нет в меню | Кнопка в **правом нижнем углу главного экрана** (TitleScreen), не в списке серверов и не в настройках мода. |
| `bad server address` | Формат `host` или `host:port`, без пробелов, без `mc://`, без пути. |
| `bad nickname` | 3–16 символов, только `A-Z a-z 0-9 _`. |
| `no passwords entered` | Поле паролей пустое или не сохранилось — нажать **Начать** ещё раз. |
| `connect failed ...` | Сервер недоступен или порт закрыт. Авто-реконнект будет пробовать снова. |
| Вошёл, но ничего не отправляется | Не написал `.start`. Либо включить **Авто-старт**. |
| Ни один пароль не признан верным | Не совпали шаблоны. Откалибровать по живой панели. |
| Все пароли «сгорели» мгновенно | Ответы сервера не распознаны или сервер не поддерживает команду входа. |
| Кик → реконнект по кругу | Сервер даёт временный бан по IP либо слишком мал **Реконнект**. |
| `Attempt to connect while already connecting` в логе | Мод отбросил лишний запрос, пока предыдущий не завершён — это нормально. |
| Обзор не открывается | Игра запущена с `-Djava.awt.headless=true`; системный проводник недоступен. Вставь путь в поле или текст в большое поле импорта. |
| Прокси не подключается | Проверить его кнопкой **Проверить**, убедиться, что адрес сервера доступен, и что формат строки верный. При включённом прокси прямого fallback нет. |
| Стоит мод **In-game Account Switcher** рядом | Оба мода пишут сессию клиента. AuthProbe переписывает ник перед каждым подключением, но если во время прогона переключить аккаунт в IAS — ник собьётся. Не трогать IAS во время прогона. |
| `Duplicate handler name: forge:vanilla_filter` | Баг Forge при переводе игрока на лимбо-сервере. Обновление Forge 47.4.28 его не лечит; мод обходит его сам, пропуская повторную установку фильтра. Если ошибка осталась — проверь, что установлена именно 1.6.1. |

<a id="limits"></a>

## ⚠️ Ограничения

- Только **offline-mode** (пиратские) серверы.
- Только клиентская сторона.
- Конфиг **не шифрован**: пароли и прокси лежат открытым текстом.
- Одна отправка на пароль — намеренно жёстко. Исключение одно: повтор того же пароля после паузы сервера при включённой умной задержке (до трёх раз).
- Прокси-режим fail-closed: при сломанном прокси прямого подключения не будет.
- Автоматической замены прокси по неудачной проверке пока нет — есть ручная кнопка ротации.
- Тайм-аут ожидания ответа — 3000 мс, в интерфейсе не вынесен.
